## Commands

```bash
uv sync                                   # install deps + dev group
uv run pytest                             # full suite (has -n auto + coverage gate ≥80%)
uv run pytest tests/test_x.py::test_y -o addopts=""   # ONE test — clears -n/--cov so the
                                          # coverage gate doesn't fail on a partial run
uv run ruff check --fix . && uv run ruff format .
uv run mypy src/
```

- **Rendering tests** need Chromium (`uv run --project . playwright install chromium`) and `gs`/`qpdf`/`verapdf` on PATH. They are marked `requires_chromium` / `requires_tools` and auto-skip (see `tests/conftest.py`) when absent. Some also shell out to `pdftotext` (poppler) to read the text layer back out of a produced PDF, and PDF/A output needs an sRGB ICC profile (`default_icc_profile()`; on Linux `icc-profiles-free`).
  **The skips are not free**: without those tools enough of the suite drops out that the `fail_under=80` coverage gate fails — a red `uv run pytest` on a machine missing `verapdf` usually means *missing tool*, not *broken code*. `ci.yml` installs all of them (veraPDF via its installer + `.github/verapdf-auto-install.xml`, since it is not packaged for apt).
- Markers: `slow` (full-pipeline end-to-end), `requires_chromium`, `requires_tools`. Only the latter two auto-skip.
- **IMAP tests** (`test_imap.py`, GreenMail parts of `test_fetch.py`) need a local GreenMail server; they skip if `localhost:3143` is closed:
  ```bash
  docker run -d -p 3025:3025 -p 3143:3143 \
    -e GREENMAIL_OPTS='-Dgreenmail.setup.test.all -Dgreenmail.auth.disabled -Dgreenmail.hostname=0.0.0.0' \
    greenmail/standalone:2.1.0
  ```
  `-Dgreenmail.hostname=0.0.0.0` is **required**, not cosmetic: without it GreenMail binds to `127.0.0.1` inside the container, so the published ports accept connections while nothing answers behind them — which surfaces much later as `SMTPServerDisconnected`, not as a refused connection. CI runs the same image as a service container (see `ci.yml`), so the IMAP tests no longer skip there.
- **Test helpers**: `pythonpath = ["."]` in `pyproject.toml` makes `tests/mail_builder.py` importable as `tests.mail_builder`. Every fixture mail is *built* by `build_mail()` rather than stored — `tests/fixtures/eml/` exists but is empty, so do not look there for samples. `asyncio_mode = "auto"` — async tests need no `@pytest.mark.asyncio`.
- **Release**: `bump-my-version bump micro` (edits `src/imaparc/__init__.py` **and** the version line in both `README.md` and `README.en.md`, commits, tags `vX`). `scripts/release.sh dev` bumps `.devN` on `dev`; `scripts/release.sh prod` bumps micro, `prod --new-month` bumps the month instead (**never both** — a month bump already resets micro to 0, so running micro after it would skip `.0`). Pushing the `v*` tag triggers `release.yml`, which builds the distribution and creates the GitHub release (`.devN` tags → marked pre-release). **No PyPI publish** — imapArc is installed straight from the repository with `uv tool install git+https://github.com/jcmx9/imapArc.git`. After release, `git branch -f main dev` and push `dev`, `main`, the tag.
- **Local reinstall of the CLI** while iterating: `uv tool install --force .` (or `git+ssh://git@github.com/jcmx9/imapArc.git`).

## Architecture

imapArc has **two decoupled phases** plus an `all` command that runs both, all driven by one `profile.yaml`. Everything downstream of a source is blind to whether a mail came from IMAP or disk (`RawMail` in `sources/base.py`): fetch feeds it from `sources/imap.py`, render from `sources/eml.py`, which reads the `output/eml/` directory the fetch phase wrote — that directory *is* the interface between the two phases.

### CLI (`cli.py`) — subcommands, one option model
- `imaparc` (no subcommand) → **help** (`no_args_is_help=True`; the `@app.callback` holds only `--version`). Click exits 2 in this case.
- `imaparc all` (`run_all`) → the **full pipeline**: `_do_fetch` then `_do_render(respect_pdf=True)` over all profiles.
- `imaparc fetch` → `_do_fetch` only. `imaparc render` → `_do_render(respect_pdf=False)` (renders **every** profile, ignoring the `pdf` flag).
- `imaparc restore` → `restore.py` uploads archived `.eml` back to a server (IMAP `APPEND`) — the **only** place imapArc creates mail on a server, and it modifies nothing that is already there. Idempotent via `contains_message()`: the Message-ID travels with the mail where the UID does not, so a repeat run adds no copy. The hit is confirmed against the ENVELOPE **subject**, because the sender picks the Message-ID and a collision would otherwise make a *different* mail count as already present. The envelope *date* is deliberately not used — servers return it naive in their own zone. That property is the point — one restores precisely when unsure whether the mail is still there. `--folder` is created and subscribed if missing; the `Date` header becomes the server-side INTERNALDATE, or the mail sorts to the bottom of every mailbox view as if it had just arrived.
- `imaparc verify` → `verify.py` checks an *existing archive* (as opposed to `doctor`, which checks the *installation*): duplicate folders, unrendered `.eml`, folders missing their PDF or manifest, leftover `.staging-*`. **Read-only on purpose** — which of two duplicates to keep needs judgement, and an archive built to stay untouched must not be rewritten silently. Exit 1 only on real damage (a folder without its PDF, which the atomic rename should make impossible); warnings must not fail a scheduled check or the signal stops meaning anything. The report groups repeated warnings per profile (`-v` lists them individually) because an archive can hold hundreds of duplicate folders — but `FAIL` findings are always printed in full, since summarising is a convenience for the noisy kinds and never a reason to fold away the one finding that costs data.
- `imaparc doctor` → `doctor.py` diagnoses the install (tools, Chromium revision, ICC, config, `.env`, Finder action, IMAP login; `--offline` drops the last). Every probe converts its own failure into a `Check` — a broken environment is the *subject*, so nothing here may raise. The Chromium probe reads the expected revision from Playwright's `browsers.json` and looks for it on disk rather than launching a browser: launching is slow and prints asyncio teardown noise, and only the revision catches the real failure (two environments with different Playwright versions evicting each other's build).
- `imaparc init` → `bootstrap.py` writes `~/.config/imaparc/{.env,profile.yaml}`. `imaparc add-profile <name>` appends one `bootstrap.profile_block`. `imaparc list-profiles` prints a rich `Table` of the parsed profiles (`_match_summary`/`_after_summary`). `imaparc sync-profiles` rewrites `profile.yaml` via `bootstrap.render_profiles_file` (values kept active, unset options commented; backs up first, restores on a parse failure). `imaparc reset` clears the delivery state; `--profile <name>` clears only that profile's rows, so fixing one profile's rules does not send every other profile through the whole mailbox again. Rows written before the `profile` column existed carry NULL, are unreachable by a targeted clear, and are *counted in the output* rather than passed over.
- `imaparc eml [PATHS...]` → `adhoc.py`, **file mode**: renders `.eml` files from anywhere into the profile archive. The profile is derived from the headers via `profiles.matching_profiles()` (the `matches()` + `attachments_match()` rules; IMAP `folders` ignored); several matches → filed into each, none → `fallback_profile(root, name)` = `<root>/00_Mails` (`--root`, default `~/imapArc`). The PDF goes to `<output>/<basename>.pdf`, and — in a pass after every render has finished — only once a PDF exists for **every** target does `sources.deliver.file_away()` copy the `.eml` into each `eml-Archiv/<output name>/` and then remove the source. Load-bearing details: `file_away` never deletes a source that *is* one of the delivered paths (rendering a mail out of the eml-Archiv would otherwise delete it as its own duplicate) nor one whose bytes changed since reading; the user's source directory is never chmod-ed; directory arguments are **not scanned recursively**; and **`allow_remote` is hard-wired to True** — a hand-picked mail should render as sent. No IMAP, no `.env`, no `StateStore`; a missing `profile.yaml` means everything goes to `00_Mails`. Until 26.11.3 this command rendered in place (`<basename>/` beside the `.eml`, the `.eml` moved in) — `rerender_check.py` still recognises those folders as kind `eml`; flat PDFs are kind `flat`, proven by the hash in their XMP only.
- `imaparc install-service` → `service.py`. `install_action(platform, …)` and `action_hint(platform)` take the platform **as an argument** rather than reading `sys.platform`, so both branches are testable — see the Gotchas for why patching it is not an option. macOS gets an Automator Quick Action in `~/Library/Services`; everything else an XDG Desktop Entry in `~/.local/share/applications`, which Nautilus, Dolphin and Thunar read for "Open With". Load-bearing details, each found the hard way: `AMDocumentVersion` must be the **string** `"2"` (an int makes Automator die with `unrecognized selector objCType`); the Desktop Entry needs `%F`, not `%f` (the latter passes only the first selected item and drops the rest without a word); and the `imaparc` path must be **absolute** in both, because neither a macOS Service nor a file manager resolves names against the user's shell PATH. The plist layout was derived from a working hand-built Quick Action — when changing it, diff key *types* against one, not just values. `automator -i a -i b` only ever passes the **first** input (a CLI artefact; the reference workflow behaves identically), so multi-selection can only be verified in the Finder itself.
- Shared `_Xxx Opt` annotations + `_do_fetch`/`_do_render`/`_select_profiles` keep the modes consistent. `--profile <name>` restricts any mode.
- Config paths default to XDG (`_config_dir()`, `_state_path()`), resolved **at import** — tests must pass explicit `--env`/`--profiles` rather than patching `XDG_CONFIG_HOME`.
- **Verbosity** follows the project's 4-level scheme (`-Q` / default / `-v` / `-vv` → `_verbosity()` → `RunConfig.verbosity`), mapped to console levels **`CRITICAL+1 / WARNING / INFO / DEBUG`**. The per-mail lines are `INFO`, so they appear from `-v` — the default stays bars-and-summary. Until 26.8.9 levels 1 and 2 were *both* `INFO`, so `-v` changed nothing on screen despite the documented "+ Entscheidungen". `--log-file` receives output **even at `-Q`** (that is what makes silent mode usable for cron), and its own level is unaffected by this mapping.
- **Progress bars** live in the orchestrators, not the CLI: `fetch.run_fetch` (open-ended, its total grows as each folder is scanned — the count is unknowable up front), `render_run.run_render` and `adhoc.run_adhoc` (total known from the file list). All three write through `console.make_progress`; a new orchestrator without one leaves a long run looking hung. Console output goes through the single shared Rich `Console` in `console.py` — `RichHandler` and the `Progress` bar must share it, or log lines corrupt the live display. Expected third-party chatter (`img2pdf`, `PIL`) is raised to ERROR; `logging.captureWarnings(True)` routes stray warnings through the same path.

### Profile templating (`bootstrap.py`)
- `render_profile_from_raw(raw)` is the **single source of truth** for a profile's YAML layout: required fields (name, account, output) + folders/pdf active; every other option present but commented with its default. `profile_block` (init/add-profile) feeds it an example dict; `sync-profiles` feeds it each parsed profile so real values stay active. Values are serialised inline with `_kv` (a bare YAML value, not a `{k: v}` mapping — flow style on the whole dict would emit braces).

### Config & matching (`accounts.py`, `profiles.py`, `config.py`)
- `.env` → `Account` (password is a `SecretStr`). `profile.yaml` → `Profile` (pydantic). `load_profiles(accounts=None)` skips the account-exists check for the render path (no `.env` needed).
- `Match` rules (all AND across kinds): `domains`/`addresses` (searched in the `mode` header fields: from/to/cc/bcc), `subject` (regex **or** wildcard-pattern list), `attachments` (required file types, checked on the body), `folders`+`recursive`, `since`/`until`, `larger`/`smaller` (sizes as `5MB`/`500KB`/bytes via `parse_size`, strict like IMAP `LARGER`/`SMALLER`). `matches()` is header-only; `attachments_match()` needs the parsed body.
- `config.py` holds the *runtime* config, distinct from the user-facing profile: `ToolPaths.resolve()` locates `gs`/`qpdf`/`verapdf` **once per run** (missing ones → one `ToolNotFoundError` listing all of them), and `RunConfig` carries verbosity, `jobs`/`gs_jobs`, `allow_remote`, the attachment size/timeout limits and the naming pattern. `default_icc_profile()` picks the first existing sRGB profile from `ICC_CANDIDATES` (macOS, then the usual Linux locations) and is resolved per `RunConfig`, not at import.
- All errors derive from `ImapArcError` (`exceptions.py`); the CLI catches those for user-facing messages, so new failure modes belong in that hierarchy rather than as bare `RuntimeError`s. Two subclasses live next to their raiser instead of in `exceptions.py`: `PdfEncryptedError` / `PdfCorruptError` in `pdf/normalize.py`.

### Fetch (`fetch.py`, `sources/imap.py`, `state.py`)
- **One scan serves every profile watching the folder.** Server-side narrowing (`SINCE`, `LARGER`, `SMALLER`) is therefore only applied where *all* of them agree — `_earliest_since`, `_common_larger`, `_common_smaller` return None as soon as one profile sets no bound, because a tighter search would drop that profile's mail before any per-profile check runs, and nothing would report it. The bounds are an optimisation; the decision stays in `matches()`.
- Per folder: `conn.scan()` lists candidates by **ENVELOPE only** (cheap, plus `RFC822.SIZE` for the size rules — same FETCH, no extra round trip); `matches()` runs on those headers; the full body is pulled via `fetch_body()` **only for a header match** (and once, lazily, when an `attachments` filter needs it — see `_match_candidate`).
- The state store records **delivered UIDs** (dedup), *not* a high-water mark — so every run re-evaluates all mail against the *current* profiles, and a changed/added profile picks up old mail with no manual reset. Unmatched mail is never marked.
- On a match: `deliver_eml()` → `state.mark_delivered()` → `_post_fetch()` (label, then move **or** delete — mutually exclusive; a label failure is isolated so it can't block the move/delete). This order means nothing is touched on the server before the local archive is durable. A profile with an `after_fetch` action also re-applies it to an **already-delivered** message still in the folder (a prior move/delete that failed is retried) — but only when the mail's `.eml` exists **now** in `output/eml/` (guards against deleting the sole copy after the path changed); move targets resolve to the server's namespace via NAMESPACE and are subscribed.

### Storage layout & invariants (`sources/deliver.py`, `storage.py`, `pipeline.py`)
Since 26.11.6 the archive is **flat**: per profile, the `.eml` live in `profiles.archived_eml_dir(output)` = `<output parent>/eml-Archiv/<output name>/<basename>.eml` (fetch delivers there; render reads from there; nothing moves afterwards), and (when `pdf: true`) each mail is **one file** `<output>/<basename>.pdf`. **`<basename>` is shared** across the `.eml` and the PDF: `build_base_name()` → `YYYY-MM-DD_hh-mm-ss_PROFILE_SUBJECT` (sanitised: illegal→`_`, `.`/`,` in subject and profile name→separator since 26.11.2 — the date part keeps a dotted `date_format` —, whitespace/underscore runs→single `_`). Timestamp = `Date` header, fallback IMAP `INTERNALDATE` (fetch) / eml mtime (render). The scheme is configurable per profile (`filename_pattern`, `date_format`) — and **both phases must read it from the same `Profile` object**: `fetch.py:_basename_for()` names the `.eml`, `render_run.py` passes it into `RunConfig` for the folder. They were out of step until 26.8.6 (only render honoured it), which would have split the two halves of the archive apart with no error at all. `tests/test_fetch.py::test_fetch_and_render_agree_on_the_base_name` nails that down.
- **PDF contents**: body + attachment pages, bookmarks ("E-Mail", each section separator, "Anhang N: name" — set by `provenance.stamp()` after Ghostscript, which would drop them), the `.eml` embedded as associated file (`/AFRelationship /Source`), every attachment that did not become pages embedded too (`/Data`, unless over `max_attachment_bytes`), and the identity (sha256 + Message-ID) in the XMP. No attachment originals, no manifest, no `_mailonly.pdf`. Embedded-file names are made unique and the `EmbeddedFiles` name tree sorted (spec requirement).
- **Legacy layouts are read, never rewritten**: per-mail folders with `.imaparc-manifest` (directly in `output` or in `output/pdf/`) count as rendered (`pipeline.archive_entries`, `is_rendered`, `stored_identity`); a legacy `<output>/eml/` inbox is still rendered and its mail then moved into the eml-Archiv by `file_away` — after the whole gather, so a copy skipped while its twin rendered is archived in the same run. Anything looking for a profile's `.eml` checks both (`profiles.eml_dirs()`): fetch's after_fetch guard, `verify`, `rerender_check._profile_emls`.
- **Atomic = complete**: the PDF is written by `write_readonly` (temp file `.tmp-*` in the same directory, fsync, rename), so its presence means the mail is fully rendered; `sweep_staging()` removes leftover `.tmp-*` files (and legacy `.staging-*` folders) before a run. **Identity lives in the PDF's XMP** (`provenance.identity()`, same line format as the old manifest: Message-ID line + `sha256:` line); `ArchiveIndex.scan()` reads it from every PDF once per output directory and run (pikepdf opens lazily, so it is cheap). The hash decides, because the *sender* picks the Message-ID and nothing enforces the uniqueness RFC 5322 asks for; legacy systems emit `<1@localhost>`. `same_mail()` prefers a hash match and falls back to the Message-ID only for pre-26.8.12 manifests. A PDF recording no identity under a wanted name is a foreign file: disambiguated around, never overwritten. Concurrent renders share a `claimed` **mapping of name → identity**, not a set of names: until 26.8.7 it held names only, so a mail delivered twice (Gmail All Mail + label, two UIDs) rendered twice. `imaparc verify` reports such pairs; the fix does not reach backwards.
- **Invariants**: files `0400` (read-only content), dirs `0700` (private but owner-manageable — you can delete/reorganise without unlocking), atomic write (temp+fsync+rename), **never overwrite** (`disambiguate()` → `…-2`, enforced in code, not by permissions). Never-overwrite guards against *loss*, so `deliver_eml()` makes one exception: if a file under the base name already holds **byte-identical** content it is reused and nothing is written — a `-2` copy of identical bytes protects nothing. Size is compared before content so a large message is not read off disk needlessly. `writable_dir()` is now effectively a no-op (dirs already 0700) but kept for robustness.

### Render pipeline (`pipeline.py`, `render/`, `html/`, `attachments/`, `pdf/`)
`render_mail()` builds three body renditions in a headless Chromium `BrowserPool`: **faithful** (`fit_page=True` — the whole mail laid out at a fixed reference width and rendered as **one tall vector page** (a single page, so no internal pagination; the guard's `* { page: auto }` makes named page breaks inert), then scaled aspect-preserving onto one A4 via a pikepdf overlay in `render/pdf_render.py` — stays vector/searchable and small; exotic-CSS layout is best-effort), **reflowed** (full size, Chromium-paginated; `_fit_width` measures the content width — 1:1 when it fits A4 portrait, scaled down if it overflows — **always portrait**, never landscape since 26.11.0; the guard's `pre { white-space: pre-wrap }` keeps Apple Mail's one-`<pre>`-per-quoted-paragraph from forcing that scale-down), and **plain-text**. A mail whose HTML is a trivial text wrapper (`html_is_trivial_wrapper`) skips the two HTML renditions entirely. Since 26.11.0 that includes the scaffolding mail clients put around a plain reply — quotes, simple lists, `pre`, a `font` face, links whose text *is* their target — which is most replies; a link whose text differs from its target, or a coloured `font`, still counts as rich. For an HTML-only mail `html_to_text` then supplies the text and prefixes quote levels with `>`. Page margins are 20 mm (25 mm left) via `Rendition.margin_mm`/`left_mm`. The header block above every body comes from one place, `render_html._header_fragment` (inline-styled, Thunderbird's two grey bands), for the HTML and plain-text renditions alike. It then appends attachment pages (PDF 1:1 via qpdf, images via img2pdf, txt/md typeset) or an info page for unconvertible/Office types (kept as originals, never converted), then merges → PDF/A-3b via Ghostscript, then `pdf/provenance.stamp()` writes the mail's SHA-256 and Message-ID into the XMP (custom `imaparc` namespace — PDF/A demands the `pdfaExtension` schema declaration beside it, or veraPDF fails) and embeds the `.eml` into the full PDF as an associated file (`/AFRelationship /Source`, Subtype `message/rfc822`). pikepdf saves with `compress_streams=False`: PDF/A forbids a filter on the metadata stream. Validated with veraPDF. HTML is made self-contained first (`html/inline.py`): `cid:` → `data:`, remote resources stripped (tracking-pixel removal), scripts/handlers removed. Remote images are **opt-in** (`--allow-remote-images`). A four-layer network lockdown in `render/browser.py` blocks all fetches by default.
- **Concurrency**: one `BrowserPool` (one Chromium process) per run, shared across mails; `_run_render` gathers the per-mail coroutines behind an `asyncio.Semaphore(config.jobs)`. `jobs` comes from the profile and is overridden by `--jobs/-j`; `gs_jobs` separately caps the Ghostscript subprocesses, which are the memory-hungry step.
- **Parsing & classification**: `mail/parser.py` turns raw RFC-822 bytes into `ParsedMail` (`mail/models.py`) — it picks the displayed body parts first and splits *everything else* into attachments vs. `cid:`-referenced inline resources, so an inline logo never becomes an attachment page. `attachments/classify.py` maps each part to an `AttachmentKind` (`PDF` / `IMAGE` / `TEXT` / `OPAQUE`) and **does not trust the declared MIME type** — clients routinely label PDFs and images `application/octet-stream`, so a positive magic-byte sniff wins. A new convertible format needs an entry in the type/extension sets *and* in `sniff_mime()`.
- **Page furniture** is Jinja2, not string-built: `html/templates/` holds the mail header block, the attachment separator/info pages and the typeset-text pages, all sharing `base.css`; `html/render_html.py` is the only renderer of them, and `humanize.py` supplies the user-visible date/size strings (deliberately a *different* date format from the filename one in `naming.py`).
- **Reporting** (`report.py`): `RunReport` accumulates `RenderResult`s and veraPDF findings. A non-compliant PDF is tolerated and listed (an exotic attachment can resist conversion).

## Gotchas

- **Never delete or move a PDF in an archive** — not from code, not by hand, not into a trash folder. imapArc has no `dedupe` command and `verify` stays read-only *by decision*, not by omission (2026-08-03). Archives exist that hold PDFs whose `.eml` is long gone, so no heuristic can tell from the outside whether a PDF is the only copy left. Report duplicates; never resolve them. The one sanctioned exception is `scripts/rerender-apply.sh` (2026-11-12), a tool the **user** runs to set aside folders before a re-render — and only folders `scripts/rerender_check.py` proves rebuildable (manifest hash, or for pre-26.8.12 manifests Message-ID plus the PDF's own text layer). Claude never runs its apply step against a real archive; `rerender-list.sh` is read-only and fine to run. The list step never descends into `eml-Archiv/`, `emlinput/` or `pdf-Löscharchiv/` (the conventional `--move-to` target beside the profiles); apply refuses a target inside a profile directory. Apply writes `collect.sh` (moves every pending `.eml` into `~/imapArc/emlinput` via `file_away`, logs origins) and `render.sh` (`imaparc render`, then `imaparc eml` on that directory) — both run by the user, like apply itself.
- **Do not monkeypatch `sys.platform`.** `sysconfig` derives module names from it, so a patched `"linux"` on macOS makes unrelated imports fail with `ModuleNotFoundError: _sysconfigdata__linux_darwin`, and test outcomes start depending on import order. Pass the platform as an argument instead — that is why `install_action`/`action_hint` take one.
- **GreenMail mangles INTERNALDATE at 12:00.** A mail sent with `12:40:48` reads back as `00:40:48`; every other hour is fine (`hh` instead of `HH` in its formatter). Verified against plain `imapclient` with no imapArc involved — do not go looking for this in `restore.py`.
- **`.eml` and PDF folder names drift apart, by design of two counters that do not talk.** `deliver_eml()` hands out the `-2`/`-3` suffix for the `.eml`, `_resolve_output()` for the folder, so a mail delivered twice ends up as e.g. `X-2.eml` beside a folder `X-3`. Nothing is lost — the folder is still reachable through its manifest — but **never pair a `.eml` with its folder by name**. `verify._unrendered()` did until 26.8.14 and called 1014 rendered mails unrendered in one real profile, hiding the two that were. Match on the manifest instead, Message-ID first (readable from the header block alone) and the content hash only for what that leaves open.
- `render` needs no `.env`; `fetch` does. `eml` needs no `.env`; it reads `profile.yaml` when present (else everything goes to `00_Mails`). Tests must pass `--profiles` and `--root` to `eml`, or it files into the real `~/imapArc`.
- Single-test runs must pass `-o addopts=""` or the `fail_under=80` coverage gate fails.
- `mypy --strict` is enforced; only `img2pdf`, `pillow_heif` and `imapclient` are exempted via `ignore_missing_imports` — a new untyped dependency needs an explicit override with a reason.
- **Python 3.14 is excluded** (`requires-python = ">=3.12,<3.14"`): 3.14 made `imaplib.IMAP4.file` a read-only property and imapclient assigns to it while subclassing, so every IMAP call raises `AttributeError`. Fixed upstream, unreleased as of imapclient 3.1.0. Verified per version against live GreenMail — 3.12 ok, 3.13 ok, 3.14 broken. Re-open the bound when imapclient releases.
- **Do not swap imapclient for `imap-tools`** — evaluated 2026-08-01 and rejected on measurement, not taste. imapArc's cheap scan sends `FETCH (ENVELOPE INTERNALDATE)`, letting the *server* parse into structured fields; `imap-tools`' nearest equivalent (`headers_only=True`) sends `BODY.PEEK[HEADER]`, i.e. the whole raw header block (kilobytes per mail with Received chains and DKIM) for the client to parse. Preserving current behaviour would mean bypassing its high-level API via `mb.client.uid(...)` everywhere — plus reimplementing imapclient's ENVELOPE address/RFC-2047 decoding. More code, not less. It *is* the right library for apps that consume mail; imapArc wants raw bytes and server-parsed envelopes because it archives.
